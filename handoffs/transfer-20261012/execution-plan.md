## Architecture changes

Maintain the independent `TransferSem` specification and existing exact indexed relation. Add three thin final modules, with names chosen when their concrete contracts are implemented: soundness, legal-input completeness, and native runtime consequence. Give each a precise list of remaining premises and the existing theorem that will discharge each one. Compose those modules into one final audit entrypoint.

Build the active dependency closure from the latest reviewed source selection. Select one authenticated source per logical module; resolve incompatible variants explicitly. Keep historical packets and rejected sources recoverable outside that closure. Do not copy every old project, import the whole historical union into a root, or rename every reviewed module. Minimize duplicate cache storage and preserve platform-specific proof objects separately.

Use indexed, exact row partitions with small checked leaves and balanced composition. Prove recurrences symbolically. Introduce a small semantic fact interface for each consumer family so downstream proofs do not unfold million-node data or wide match tables. Keep facts connected to their precise row indices and source meanings; the interface cannot define correctness from generated rows.

Construct one legal seed in a fixed order, with explicit read/write sets and preservation lemmas. Derive aliases, word bounds and meanings from the legal input encoder. Apply arithmetic completion once. Prove all assertions on that final assignment and use the accepted fixed-point/uniqueness results to transport independently established component facts when their full input agreement is available. Equality of public fields alone does not establish seed agreement.

For native work, build a reachable Transfer caller census first. Map each concrete operation to an existing modeled theorem and list the unproved refinement beside it. Prioritize the paths from proof admission through delivery and persistence. Add primitive lemmas only when a reachable caller needs them. Retain permitted compiler/backend/OS trust boundaries explicitly; do not replace owned field, codec, ordering, rollback or recovery obligations with assumptions that assert their desired results.

## Lessons from earlier failures

| Observed failure | Change to the completion approach |
| --- | --- |
| Older checkouts and locks were mistaken for the campaign baseline | Every task starts with exact security source selection and runtime SHA; never launch from the chat cwd by default |
| A full-row provider was confused with independent legal assertion truth | Track row identity, arbitrary-assignment semantic soundness and legal-input truth separately |
| Selected-row inclusion was confused with full construction coverage | Soundness uses full-to-local restriction; completeness supplies exact reverse coverage of every stored row and padding |
| Overlapping/different-assignment counts and pilot duplicates inflated progress | Report exact sets and the assignment identity; use final endpoint closure as the progress measure |
| Wide concrete checks, monolithic walks and repeated unfolding exceeded memory | Small kernel checks, symbolic recurrences, opaque semantic interfaces and balanced aggregates; representative benchmarks before scaling |
| An imported historical library port consumed work after a smaller curve route had closed the need | Reuse the accepted actual curve/order/cardinality capstones; no new Hasse port |
| A modeled finalizer had the wrong native source order | Audit source order and errors before integration; use the corrected source-ordered finalizer/driver and retain the rejected history |
| Binary RowSpool was fed to a JSONL reader | Preserve the repaired bounded framing adapter and its controls; do not recapture already qualified data |
| Increasing metadata variants, scratch copies and decoded history exhausted disk | One active import graph; reuse authenticated memoization and existing lossless archives; remove disposable caches before copying evidence |
| Authentication, capacity and remote-service failures resembled proof failures | Inspect processes and receipts after reconnect; record uncertain message delivery; avoid duplicate sends/controllers and never classify service failure as semantic rejection |
| Compiler success with rejected warnings or missing audits was promoted too loosely | Qualification requires the complete expected type/axiom report and accepted audit outcome, including every final declaration |
| A native shell launcher failed on CRLF before reaching any test | Generate platform scripts as explicit LF bytes and validate the prepared successor; retain the launch failure without semantic control credit |

## Scheduling and resource controls

- One heavy verification job per physical host. Mac and desktop may build concurrently; Lean, Cargo and model checking on the same host share the lane. The Mac lane is this session; no replacement subagent or old relay is needed for planning.
- One Lake process per host, `LEAN_NUM_THREADS=1`, narrow named modules and finite heartbeats. Keep the campaign's existing heap/RSS/time guards. The historical Mac guard is 2 GiB heap, 4 GiB process-group RSS and 240 seconds per module; the historical desktop guard uses 1,536 MiB heap and 240 seconds. Authenticate each current runner before launching; do not assume a historical value describes an unpublished successor.
- Benchmark representative first/middle/high/final leaves and aggregators after a generator architecture change. A warm import floor must be measured separately from new elaboration cost.
- Reserve practical free disk before resuming. The existing 2 GiB admission floor is an emergency minimum; use [the cleanup suggestions](mac-cleanup.md) to reclaim disposable caches and obtain at least 20 GiB headroom. Preserve sources, original receipts and failed histories.
- After a crash or unknown send result, inspect process ownership and immutable receipts before resuming. Terminate only this task's owned process group when a guard requires it.
- Review source and receipts while the other machine builds. Review/publication should not impose per-module waits on routine proof work. Serialize shared publication with one coordinator and full-SHA acknowledgements.
